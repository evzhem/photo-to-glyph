# Формат .gfont

Статус: установленные в постановке задачи факты; проверка на разрешённом реальном файле и KDraw — **M9**. Эта спецификация не утверждает, что масштаб или все возможные записи архива уже проверены.

## Контейнер

`.gfont` — ZIP-архив. Имя записи глифа — **десятичный код символа Unicode**, например `1046` для «Ж». Не добавлять расширение записи на основании догадки.

Реализация — только `java.util.zip` и собственная сборка/чтение бинарных структур. Не использовать сторонний gfont-кодек и не копировать чужой код. Тестовые наборы создавать самостоятельно; сторонние `.gfont` не коммитить.

## Бинарная запись глифа

Все многобайтовые поля — **big-endian**.

| Порядок | Поле | Тип | Значение |
| ---: | --- | --- | --- |
| 1 | Код символа | `uint16` | Unicode-код символа |
| 2 | Количество float | `uint32` | Чётное число **скалярных координат**, не количество точек |
| 3 | Координаты | `float32[]` | Пары `x, y`, то есть `floatCount / 2` точек |
| 4 | Количество флагов | `uint32` | Размер следующего массива |
| 5 | Флаги | `uint8[]` | Начало/продолжение штриха |

Флаги:

- `0` — начало нового штриха: перо опускается в этой точке; из предыдущего штриха до неё рисующая линия не проводится.
- `1` — продолжение текущего штриха.

Предполагается один флаг на точку и `0` у первой точки. Это естественная интерпретация известных полей, **но равенство flagCount и pointCount и поведение пустого глифа надо подтвердить на реальном файле**, а не выдавать за дополнительно установленный факт. Читатель должен валидировать длины/границы и сообщать несовместимость, не молча угадывать.

`uint16` не представляет Unicode-коды выше `65535`. Для текущих кириллицы/латиницы/цифр/базовой пунктуации этого достаточно; поддержку supplementary-plane символов нельзя обещать без подтверждения формата.

## Координаты и метрики

- В `.gfont` ось Y направлена **вниз**.
- Базовая линия — `y = 0`.
- Основная часть букв лежит в отрицательных Y.
- Хвосты «д», «р», «у» уходят в положительные Y.
- Межбуквенный шаг не хранится: KDraw вычисляет его из ширины глифа и настройки «Размер шрифта».
- В модели PhotoGlyph Y направлена **вверх**. Экспорт должен явно переводить координаты относительно базовой линии, а не путать растровые и модельные системы.

## Пока неизвестно — не выдумывать

1. Единицы координат и связь с кеглем/«Размером шрифта» KDraw.
2. Наличие и назначение служебных записей ZIP.
3. Обязателен ли файл-спутник `.gfont.txt` и каково его содержимое.
4. Дополнительные ограничения значений, пустых глифов и флагов.

До получения данных разумные допущения должны быть помечены непосредственно в коде и отчёте. Не писать неизвестные служебные записи, масштаб или текстовый спутник «для совместимости» наугад. При дальнейшем M9 acceptance реальный файл (если он будет доступен с разрешением) можно исследовать через CLI `gfontInspect`; до этого неизвестные остаются явно открытыми.

## Реализация известного подмножества — 2026-10-17

Core `GfontCodec` now writes and reads only the documented numeric-Unicode ZIP glyph records: big-endian `uint16` code point, `uint32` scalar count, `float32` coordinates, and one `uint8` pen flag per point. It flips model Y-up coordinates to the documented `.gfont` Y-down convention, keeps model coordinate units unchanged, emits no speculative service entries/companion text, and rejects unsupported records instead of silently dropping them. `GfontRoundTripTest` uses original synthetic glyphs and invokes this production codec.

В Android доступен ручной путь от подготовленной страницы к сохранённому `GlyphSet`: пользователь выделяет каждую букву, подтверждает её символ, проверяет centerline-черновик и метрики, затем экспортирует отдельный набор из библиотеки. Это не OCR и не автоматическая сегментация; связанные курсивные буквы не разделяются. `flagCount == pointCount` реализовано как явно обозначенное рабочее допущение на основании документированной структуры. Реальный `.gfont`/KDraw не проверяли. Масштаб, дополнительные ZIP-записи и совместимость остаются неизвестными; UI предупреждает об этом.

## Верификация (M9)

1. Прочитать разрешённый реальный набор вне Git, вывести имена записей, коды, числа координат/флагов, диапазоны X/Y, флаги и дополнительные записи. Не подключаться к устройству напрямую.
2. Собственный `GfontCodec`: запись → чтение → сравнение глифов, точек с точностью `1e-4` и точных флагов.
3. Проверять чётность floatCount, доступные байты, разумные пределы размеров и корректность значений, без копирования логики в тесты.
4. Экспорт собственного набора → установка в `gcodefonts` → перезапуск KDraw.
5. «Проверка недостающих слов» и реальное написание текста на бумаге.

Round-trip собственного файла подтверждает внутреннюю согласованность кодека, **не** подтверждает аппаратную совместимость и масштаб. При неподтверждённой совместимости доступны SVG/PNG, но M9 остаётся не принятым по аппаратному критерию.
