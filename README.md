# PhotoGlyph

Android-приложение для русскоязычного пользователя: при запуске открывает камеру, чтобы сфотографировать страницу с рукописными буквами; затем должно определить буквы и собрать набор почерка для перьевого плоттера. Целевое устройство — «Хорус 3 Pro» (семейство Kvenjoy), управление — через KDraw.

Плоттер рисует **линии**, а не заливки. PhotoGlyph не обводит букву двойным контуром: конвейер строится вокруг скелетонизации. Ручной редактор штрихов входит в MVP, поскольку автоматика не всегда восстанавливает почерк правильно.

Алфавит: кириллица (включая Ё/ё), латиница, цифры и базовая пунктуация. Основной интерфейс — русский; код и коммиты — английские.

## Основной сценарий: страница → алфавит

Фото страницы с рукописными буквами → приложение определяет буквы и собирает алфавит/набор почерка из того, что найдено. **Алфавит может быть неполным.** Отсутствующие буквы подставляет KDraw; PhotoGlyph не выдумывает буквы и не объединяет наборы.

Хранение локальное — на телефоне, без аккаунта и облачной синхронизации; отдельные наборы можно экспортировать для KDraw. Сейчас путь от страницы использует ручное выделение/подписание букв; автоматическое распознавание ещё не реализовано. Форматный масштаб и реальную совместимость экспорта/подстановки предстоит проверить в KDraw. Подробнее: [docs/01-требования-mvp.md](docs/01-требования-mvp.md) и [ROADMAP.md](ROADMAP.md).

## Отдельная функция: фото → чёрные контуры

По фотографии изображения приложение должно выдать отдельную картинку с чёрными контурами. Это не алфавит и не осевые штрихи почерка. В Android-коде появился отдельный camera/import-режим с просмотром результата, а в core — самостоятельная Sobel/NMS-обработка и настраиваемая чувствительность. Четыре синтетические проверки вызывают production-функции. Контурный UI, сегментация и JSON-модель прошли полный GitHub Actions Gradle/Android build, core tests и CLI smoke (run [38799609923](https://github.com/evzhem/photo-to-glyph/actions/runs/38799609923)); опубликован debug APK artifact `photoglyph-m1-debug-apk` (ID `12003392740`). Белый фон — текущий технический выбор, не подтверждённое требование; сохранение/экспорт файла не добавлены. Проверка на реальных фото и Android-устройстве ещё нужна. Подробнее: [docs/05-рисунок-по-контуру.md](docs/05-рисунок-по-контуру.md).

Подготовка страницы — промежуточный шаг, а отдельный режим чёрных контуров вторичен. В Android добавлена ручная сборка набора из подготовленной страницы: пользователь выбирает кириллицу или латиницу, затем отдельно выбирает заглавную либо строчную форму (например, `А` и `а` — разные glyphs с отдельным прогрессом), выделяет её на странице, проверяет centerline-черновик и baseline, выбирает образцы высоты, сохраняет неполный `GlyphSet`, затем экспортирует отдельный `.gfont` из библиотеки. Core хранит наборы независимо и не дополняет пропуски. Это ещё не автоматическое распознавание: связанные курсивные буквы не разделяются, labels подтверждаются вручную, pen-order и редактирование штрихов отсутствуют. Центровая геометрия использует ранний M0-алгоритм и не проверялась на реальном почерке. Масштаб `.gfont` и совместимость с KDraw не проверены. Отчёты: [docs/M3-manual-builder-report.md](docs/M3-manual-builder-report.md), [docs/M9-codec-foundation-report.md](docs/M9-codec-foundation-report.md), [docs/M5-report.md](docs/M5-report.md), [docs/04-формат-gfont.md](docs/04-формат-gfont.md).

## Песочница для проверки

В M1 добавлена браузерная **лаборатория для разработчиков**, а не пользовательский экран: пять синтетических отдельных букв, параметры и метрики ядра. Она нужна только для проверки алгоритма и не показывает основной сценарий приложения. В браузерной лаборатории загруженное изображение отправляется на тестовый сервер после согласия; не загружайте личные страницы. Подробнее: [docs/03-песочница.md](docs/03-песочница.md).

В Android-приложении при запуске запрашивается разрешение и сразу открывается полноэкранная камера; при отказе можно выбрать фото. После подготовки страницы доступна ручная сборка алфавита по одной обрезке, локальное сохранение и экспорт отдельного `.gfont`. Автоматическое распознавание и разделение связанных букв, редактор штрихов и приёмка на реальном Android-устройстве ещё отсутствуют. Экспорт и его масштаб пока не проверены в KDraw.

## Результат M0, на котором основана песочница

Спайк на **синтетике**, не на фотографиях реального почерка: пять собственных PNG 300 × 300, толщина штриха 6 px. Настоящее Kotlin/JVM-ядро выполняет BT.601 → адаптивный порог → удаление мелких компонент → Zhang–Suen → пиксельный граф → pruning → открытые полилинии → RDP → SVG.

21 тест обращается к production-коду, включая PNG-golden 20 × 20 и проверку испорченного SVG. Пять SVG содержат только явные `fill="none"` + `stroke`; замкнутых выходных полилиний нет. Естественные петли букв **сохраняются**: цикл при необходимости делится на два открытых штриха. Нулевой счётчик замкнутых полилиний не означает отсутствие циклов в геометрии буквы.

**Решение M0: B** — ось получается, но нужна дополнительная предобработка/очистка узлов. У «Ж» вместо трёх исходных рисованных линий получилось восемь графовых цепочек; диагонали ещё ступенчатые. Это не восстановление движения пера и не принятый production-конвейер M4. Реальные фото и Inkscape требуют отдельной проверки человеком.

Отчёт с полным выводом команд, метриками, ограничениями и критериями: [docs/M0-report.md](docs/M0-report.md). SVG-доказательства и CSV: `docs/m0/`.

## Архивный запуск M0 и тестов

Требуются **Java 17+**, Kotlin/JVM **2.1.21**, Python 3.10+ (стандартная библиотека), Bash и Git. Gradle, Android SDK и эмулятор на этапе M0 не используются.

Если Java и Kotlin уже установлены, задайте при необходимости `JAVA_HOME` и `KOTLINC` и выполните:

```sh
./tools/m0-check.sh
```

В этой среде нет предустановленных Java/Kotlin, а перенаправления GitHub release assets закрыты сетью. Необязательный bootstrap для Linux x86_64 загружает закреплённые по checksum инструменты в игнорируемый `.cache/`:

```sh
python3 tools/bootstrap-m0.py
./tools/m0-check.sh
```

Используются официальный пакет компилятора JetBrains `kotlin-compiler@2.1.21` из npm и локальная Temurin Java 21.0.8 из PyPI-архива `jdk4py==21.0.8.2`. Это **только локальные инструменты**: npm/pip-зависимостей продукта нет, обёртка `jdk4py` не импортируется, код и бинарники этих пакетов не коммитятся и не включаются в приложение. Ядро зависит лишь от Kotlin stdlib и стандартного JVM API, целевой байткод — JVM 17. JDK имеет собственную лицензию GPLv2 с Classpath Exception; это toolchain, не GPL-библиотека проекта.

Скрипт проверяет воспроизводимость фикстур, компилирует production JAR, **отдельно** компилирует тесты против него, запускает 21 тест и CLI smoke. SVG, промежуточные PNG и `metrics.csv` записываются в игнорируемый `.m0-work/`; JAR — в `build/m0/`. Время зависит от машины; копия одного измеренного прогона сохранена в отчёте, а не выдаётся за универсальную скорость Android.

Отдельный прогон на уже вырезанной букве:

```sh
# Используйте установленную Java или bin/java из локального bootstrap.
java -Djava.awt.headless=true -Dfile.encoding=UTF-8 \
  -cp build/m0/photoglyph-m0.jar photoglyph.cli.MainKt \
  vectorize cropped-letter.png result.svg
```

На этапе M0 полный лист и Android UI ещё не реализовывались. Сейчас Android-каркас открывает камеру при запуске, умеет импортировать/подготавливать страницу (углы, crop/rotation, перспектива и ч/б) и имеет отдельный preview контуров. Буквы ещё не распознаются. Собственные синтетические фикстуры: [tools/fixtures/synthetic/README.md](tools/fixtures/synthetic/README.md).

### M1: Gradle и настоящие проверки

Созданы модули `:core`, `:app`, `:cli`, `:tools`, официальный Gradle wrapper с checksum, ktlint/detekt и GitHub Actions. Обязательная команда:

```sh
./gradlew build :core:test :cli:smoke
```

Для неё нужны JDK 17, Android SDK 35 и доступ к Gradle/Google Maven/Maven Central. В этой Arena-среде загрузка Gradle блокируется TLS/network policy; это не маскируется как зелёная локальная сборка. Полный CI-результат и локальный результат отдельно: [docs/M1-report.md](docs/M1-report.md). [Зелёный CI на пустом коммите](https://github.com/evzhem/photo-to-glyph/actions/runs/38439241310).

Дополнительные самостоятельные проверки без Gradle:

```sh
./tools/m1-standalone-check.sh
```

Они компилируют настоящее production-ядро/CLI и исполняют те же тела тестов: 21 исходную проверку, 3 source-policy и 8 API/core-recovery сценариев. Это **не** сборка Android и не заменитель обязательного Gradle-прогона. В JUnit — 12 методов: 4 core (один исполняет исходные 21 проверки) и 8 CLI. Браузерная QA описана в инструкции песочницы.

## Экспорт и устройство

Приложение экспортирует отдельный `.gfont` через Android document picker; его установка в KDraw, масштаб и реальная совместимость ещё не проверены. Приложение **не** подключается к плоттеру по Bluetooth/COM. Внутренний SVG/PNG для диагностики алгоритма не означает, что пользовательский export этих форматов реализован или подтверждён.

Спецификация: [docs/04-формат-gfont.md](docs/04-формат-gfont.md). Единицы, кегль, служебные записи и необходимость `.gfont.txt` ещё не подтверждены реальным файлом.

## Структура

- `core/` — чистое Kotlin/JVM-ядро (`geom`, `img`, `thin`, `graph`, `export` в M0), без `android.*` и platform image I/O.
- `app/` — Android Compose/CameraX: camera-first запуск, импорт/подготовка страницы, ручная обрезка и подпись букв, локальное сохранение неполных наборов и отдельный `.gfont` export; контурный режим вторичен. Автоматическое распознавание/разделение курсивных букв, редактор штрихов и проверка в KDraw не реализованы.
- `cli/` — JVM-прогон конвейера и browser developer sandbox; ImageIO и файловые операции остаются здесь.
- `tools/` — оригинальные синтетические фикстуры и standalone-проверки M0–M2; тестовые буквы не входят в пользовательский Android flow.
- `docs/` — спецификации и проверяемые отчёты.

## Частичные алфавиты и локальное хранилище

Последнее уточнение пользователя (14.10.2026):
- Можно сохранять и экспортировать неполные наборы букв; отсутствующие символы не требуют сохранения на одном фото.
- Хранилище локальное — на телефоне, без учётной записи и синхронизации в облако.
- KDraw владеет подменой недостающих букв из других наборов. PhotoGlyph не объединяет наборы и не предоставляет fallback-метаданных внутри набора.

Сейчас пользователь может вручную выделять и подтверждать glyphs, сохранять неполный набор в app-private JSON store и экспортировать отдельный `.gfont` из библиотеки. Автоматическое распознавание, коррекция штрихов и приёмка в KDraw не реализованы; физическая проверка нового builder flow ожидает Android-устройства. Подробнее: [отчёт M3](docs/M3-manual-builder-report.md), [отчёт M5](docs/M5-report.md), [отчёт M9](docs/M9-codec-foundation-report.md).
